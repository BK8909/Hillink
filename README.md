# HILLINK

### 후기 기반 가상 고객 행동·소비·호텔 운영 전략 시뮬레이터

> **“같은 고객이 다른 날, 다른 조건으로 호텔을 방문한다면 어떤 선택을 할까?”**

HILLINK는 실제 호텔·여행·식음 후기에서 고객의 경험과 선택 기준을 찾아 가상의 호텔 방문에 적용하고, **개인별 행동 → 상품 선택·소비 → 운영 전략 실험**까지 연결하는 호텔 운영 시뮬레이터입니다.

호텔 운영자는 고객을 대상으로 행사·가격·상품·운영 조건을 마음대로 바꿔 시험하기 어렵습니다. HILLINK는 실제 후기에서 확인된 개인적 맥락을 가진 가상 고객으로 대안을 비교하고, **무엇이 달라졌는지뿐 아니라 왜 그렇게 선택했는지** 설명하는 환경을 제공합니다.

## HILLINK가 하는 일

<small>※ 아래 단계는 하나의 가상 방문 기록으로 연결됩니다.</small>

| 단계 | 수행하는 일 | 운영자가 확인할 내용 |
|---|---|---|
| **고객 이해** | 동일 작성자의 여러 후기에서 Fact·반례·반복 경험을 추출 | 경험의 원문 근거, 선호와 조건부 평가 |
| **방문 설계** | 기간·방문일·동행·날씨·행사·객실 및 상품 조건 설정 | 실제 후기와 구분되는 가상 방문 가정 |
| **연속 행동** | 실행 가능한 후보를 만들고 개인 상태·목적·기억으로 행동 결정 | 식사·휴식·활동·퇴실까지 이어지는 흐름 |
| **행동근거 추적** | 판단 전 Fact·상황·비교 대안을 최종 선택과 연결 | **왜 지금 이 행동을 선택했는가** |
| **가상 소비 집계** | 선택한 SKU·수량·가격·혜택을 거래 원장에 반영 | 고객 → 상품 → 업장 → 호텔 전체 소비 |
| **운영 전략 A/B** | 목표 업장의 미선택 원인을 진단하고 지원되는 운영 조건 비교 | 고객 이동·메뉴 변화·할인 비용·호텔 전체 순변화 |

## 핵심 기능

### 개인 후기 기반 고객 라이브러리

워커힐 방문 후기뿐 아니라 같은 작성자의 다른 호텔·레스토랑·여행 경험을 함께 검토합니다. 예약·주문·참여·평가를 구분하고, 비슷한 내용이 여러 글에 등장해도 하나의 방문을 여러 번 경험한 것처럼 계산하지 않습니다.

고객 라이브러리에는 **45개 프로필**이 정리되어 있으며, **28개는 가상 방문 실행**, 나머지는 자료 열람을 위한 프로필로 구분됩니다. 원문에 언급되지 않았다는 사실을 방문하지 않았거나 선호하지 않는다는 증거로 취급하지 않습니다.

### 호텔에서 이어지는 하루

비투숙 당일 방문부터 3박 4일까지 방문 조건을 설정할 수 있습니다. 고객은 이전 식사, 피로와 허기 *추정*, 동행, 영업시간, 대기, 예약, 시설 자격과 남은 일정을 참고해 다음 행동을 선택합니다.

규칙 엔진이 **실행 가능한 후보와 호텔 운영 제약**을 관리하고, AI는 개인 Fact·반례·현재 상태·이전 행동의 기억을 바탕으로 후보를 비교합니다. 선택된 행동은 다시 상품·운영 계약을 통과한 뒤 실행됩니다.

객실에서 저녁 시간을 보내는 것과 실제 취침을 구분하며, 단순히 일정을 채우기 위해 활동을 강제하지 않습니다. 개인 근거가 충분하면 이른 휴식이나 같은 경험을 다시 선택하는 것도 가능합니다.

### 이해하기 쉬운 행동근거

고객 흐름에서 장면을 선택하면 **관측된 성향과 후기 Fact → 판단 당시 상황 → 비교한 대안 → 최종 선택 이유 → 실제 실행·거래** 순서로 확인할 수 있습니다.

운영자에게는 자연스러운 설명과 핵심 근거를 보여주고, 내부 정책 식별자·해시·원시 JSON 같은 개발 진단은 화면의 본문에서 제외합니다. 가상 고객의 설명을 실제 고객의 발언으로 표시하지 않습니다.

### 고객부터 호텔까지 이어지는 가상 매출

```text
고객별 거래(L5) → 상품별 주문(L4) → 업장(L3) → 부문(L2) → 호텔 전체(L1)
```

선택한 상품의 판매 단위·수량·가격·혜택과 객실 및 시설 이용을 같은 실행 기록으로 집계합니다. 결제하지 않은 상품, 호텔 외부 배달, 무료·포함 혜택, 가격 미확인은 구분합니다. **가상 소비액은 실제 호텔 POS 매출이 아닙니다.**

### 운영 전략과 A/B

운영자는 목표 업장을 선택하고 고객이 그 업장을 이용하지 않은 이유를 살펴봅니다. 가격이 문제였는지, 운영시간·예약·이동 또는 상품 구성이 더 중요한지 판단한 뒤, 실제 엔진과 카탈로그가 지원하는 조건을 실험합니다.

**운영 목표 → 현재 선택 분석 → 개인·집단 전략 카드 → A/B 비교 → 운영 결론**을 하나의 흐름으로 제공합니다. 규칙 분석과 LLM 전략 분석은 동일한 카드·비교 화면을 활용하되 판단 출처를 구분합니다.

A/B는 동일한 고객·방문 조건에서 **운영 변수 하나만 변경**하는 방식으로 설계합니다. 목표 업장의 고객 증가와 다른 업장으로부터의 이동, 같은 업장의 메뉴 변경, 기존 고객에 대한 할인 비용, 호텔 전체 순변화를 별도로 보여줍니다. 지원되지 않는 상품·예약·가격 조건은 실행 가능한 것처럼 표시하지 않습니다.

## 설계 원칙

- **개인 근거 우선:** 후기의 관측 Fact·반례가 개인 판단의 중심이며, 일반 행동 패턴과 참고 통계는 자료가 부족한 부분만 보완합니다.
- **선택 전 기록:** 선택하고 나서 이유를 꾸미기보다, 실제 판단에 들어간 입력·후보·비교·선택을 연결합니다.
- **실행 가능한 호텔 세계:** 영업·시설 자격·시간·상품·가격 계약을 검증합니다. 외부 배달은 호텔 내부 F&B와의 선택 비교에만 포함합니다.
- **실행 모드 구분:** 규칙 계산, 원본 AI 판단의 정확 저장 재현, 승인된 실시간 AI 판단을 혼동하지 않습니다.
- **검증 가능한 가상 실험:** 가상 행동과 원장을 비교하되 실제 고객 행동 예측 정확도나 호텔의 인과적 매출 효과를 주장하지 않습니다.

## 실행하기

Python 3.11과 웹 브라우저가 필요합니다.

```bash
git clone https://github.com/BK8909/Hillink.git
cd Hillink/hillink
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
bash tools/start_product.sh
```

기본 주소는 http://127.0.0.1:8994/ 입니다. 포트는 `HILLINK_PORT`로 변경할 수 있습니다. 기본 실행은 외부 API 호출이 차단된 규칙·저장 재현 경로이며, 실시간 AI 판단은 **승인된 API 키와 누적 사용량 원장**을 별도로 설정해야 합니다.

설치·복원·검증 명령은 [RECOVERY.md](hillink/handover/RECOVERY.md), 연구 설계·근거 추출·평가 방법·한계는 [연구·기술 인계서](hillink/docs/research/RESEARCH_AND_ARCHITECTURE_HANDOFF.md)를 참고하세요. 새 고객을 추가하려면 [페르소나 등록 안내](hillink/handover/persona/README.md)를 따릅니다.
