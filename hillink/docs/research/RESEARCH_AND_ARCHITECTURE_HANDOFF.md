# HILLINK | 연구·기술 아키텍처 및 평가 방법

> 후기에서 관측한 개인의 경험을 **반사실적 호텔 방문의 선택 근거**로 연결하는 시뮬레이션 연구

HILLINK는 동일 작성자의 호텔·다이닝·여행 후기를 연결해 개인별 경험과 선택 기준을 추출하고, 새로운 호텔 방문 조건에서 가능한 행동을 생성·선택·실행하는 시스템이다. 최종 행동은 상품 주문과 가상 거래 원장으로 연결되며, 운영자는 가격·상품·행사 등 호텔이 조절할 수 있는 조건을 바꾸어 개인 및 고객군의 가상 선택 변화를 비교할 수 있다.

이 연구의 핵심 질문은 **“미래의 실제 선택을 맞히는가?”가 아니라 “주어진 가상 조건에서, 그 사람의 관측된 경험과 현재 상황을 연결한 선택을 근거 있게 설명하고 재현할 수 있는가?”**이다. 실제 호텔의 디지털 트윈이나 실매출 예측기를 주장하지 않는다.

## 1. 연구 문제와 접근

일반적인 고객 유형은 특정 성향을 가진 평균 인물을 설명하는 데 유용하지만, 같은 유형에서도 고객의 과거 경험·동행·시간·예약·목적에 따라 선택은 달라질 수 있다. 또한 후기 한 편에 등장한 선택만으로 반복 취향을 확정하면 당시의 제약을 개인의 고정 특성으로 오해하기 쉽다.

HILLINK는 이를 해결하기 위해 다음 원칙을 둔다.

1. **작성자 단위 근거:** 워커힐 방문기뿐 아니라 동일 작성자의 다른 호텔·식당·여행 경험을 함께 검토한다.
2. **Fact와 해석 분리:** 실제 방문·예약·주문·참여·평가·미래 계획을 구분하고, 선호 추정에는 원문과 반례를 연결한다.
3. **상황을 포함한 판단:** 허기·피로 등은 엔진이 계산한 모델 상태이며 실제 고객에게서 측정한 사실이 아니다. 방문 목적·동행·영업 조건도 별도로 관리한다.
4. **선택 전 근거:** 결과에 나중에 설명을 덧붙이는 대신, 해당 시점에 제공된 Fact·후보·상태·대안과 선택을 같은 기록에 남긴다.
5. **행동과 거래 연결:** 시뮬레이션에서 실제 실행한 행동만 상품·주문·가상 원장에 반영한다.
6. **실험 결과의 경계:** 관측된 가상 변화와 실제 호텔 운영 효과를 분리하고, 조건이 맞지 않는 비교에는 결과를 부여하지 않는다.

## 2. 전체 시스템 구조

```text
동일 작성자의 후기·경험
          │
          ▼
사건·화자·시간 구분 → 원문 Fact·반례 → 개인 성향·상황별 특성
          │
          ▼
방문 시나리오(동행·기간·날씨·행사·객실·운영 조건)
          │
          ▼
상태·기억 ── 호텔 운영 규칙 ── 실행 가능 후보·SKU·가격
          │                       │
          └────────────┬──────────┘
                       ▼
              개인 근거 기반 LLM 판단
                       │
                  운영 계약 재검증
                       │
                       ▼
               행동 실행·상태 갱신
                       │
             다음 선택 / 다음 날 방문
                       │
                       ▼
       주문·거래 L5 → 상품 L4 → 업장 L3 → 부문 L2 → 호텔 L1
                       │
                       ▼
       운영 목표 → 원인 진단 → 전략 → A/B → 운영 결론
```

### 2.1 고객 프로파일링

후기 분석은 장소명 검색에 그치지 않는다. 누가 무엇을 했는지, 언제 했는지, 관심·예약·주문·결제·실제 이용·사후 평가 중 어느 단계인지 구분한다. 같은 방문이 여러 글이나 사진에서 반복되면 독립적인 행동 사례로 중복 집계하지 않는다.

추출한 자료는 다음처럼 관리한다.

| 요소 | 의미 | 주의할 점 |
|---|---|---|
| 원문 Fact | 실제 글의 특정 구간에 연결한 경험·평가·선택 | 후기의 미기재는 미방문 증거가 아님 |
| 개인 성향 가설 | 반복 경험에서 제안한 취향·기준·관심 | 단일 사례를 영구적 선호로 단정하지 않음 |
| 반례·조건부 경험 | 만족과 불만, 후회, 재방문 거부, 특별한 조건 | 긍정·부정을 한 문장으로 평탄화하지 않음 |
| 방문 상황 | 동행·방문 목적·시간·날씨·예약·운영 가정 | 과거 여행 목적을 새 방문의 사실로 옮기지 않음 |
| 실행 기억 | 가상 방문에서 이미 한 식사·활동·거래 | 실행 기록을 실제 고객의 경험으로 재학습하지 않음 |

원문 추출 결과는 스키마 검사와 의미 검토를 분리한다. 구조적으로 올바른 JSON이라고 해서 특정 성향의 뜻이 정확하다고 승인하지 않는다. 새 작성자의 자료는 기존 사례와 분리해 검토하고, 시뮬레이션 결과가 프로필 추출 단계에 역류하지 않도록 한다.

### 2.2 행동 후보와 호텔 운영 계약

규칙 실행기는 현재 시각·위치·동행·남은 방문 기간·이전 식사·휴식·시설 이용 등을 읽고 후보를 만든다. 후보는 영업시간, 이동·대기, 투숙객/연령 자격, 예약, 행사 회차, 상품 구성, SKU, 가격·할인·포함 혜택 같은 조건을 통과해야 한다.

규칙 점수는 **행동 비교를 돕는 모델 내부 평가값**이지 선택 확률이나 실측 지불 의사가 아니다. LLM은 유효한 후보의 순위를 반드시 따르지 않으며, 개인 근거와 현재 상태에 따라 다른 선택을 할 수 있다. 최종 답변 역시 상품·시간·원장 검증을 다시 거친다.

### 2.3 LLM 판단과 연속 방문

실시간 판단은 다음 사항을 함께 고려한다.

- 관련 후기 Fact와 반례 및 그 의미
- 현재 방문 목적·동행·활동·이동·대기·영업 제약
- 직전 식사·주문·허기/포만·피로의 **모델 추정**
- 앞선 날의 실행 기억과 아직 실행하지 않은 의도
- 오늘 남은 후보와 다음 날 일정
- 무엇을 선택하지 않았으며 그 이유가 무엇인지

객실에서 저녁을 보내는 행동과 취침은 별개의 상태다. 휴식을 선택했다면 이후 재판단할 수 있고, 취침을 선택했다면 다음 날 방문으로 넘어간다. 반복 활동이나 이른 취침을 일률적으로 금지하지 않고, 당시에 사용 가능한 대안과 개인 근거가 있는지 검토한다.

실행에는 **규칙 계산**, **원본 AI 응답의 정확 저장 재현(Replay)**, **승인된 새 AI 판단(LIVE)** 경로가 있다. Replay는 모델·설정·전체 입력이 일치하는 원응답만 재생하며, 다른 방문 조건으로 답을 바꾸거나 규칙 출력을 AI의 새 판단처럼 표시하지 않는다.

### 2.4 행동근거의 역추적

설명에 사용한 근거는 해당 결정에 실제 전달된 Fact·반례·상태·후보에 연결되어야 한다. 결과를 보여주는 제품 화면은 다음 순서를 따른다.

**최종 행동 → 관측된 개인 특성 → 당시 상황 → 비교 대안 → 선택 이유 → 실행·주문·원장.**

설명의 문체는 사용자에게 읽기 쉬운 한국어로 정리하되, 저장된 원본 판단·Fact 참조·대안·거래는 변경하지 않는다. 개인 선호의 직접 근거가 약한 경우에는 일반적인 상황 판단이라고 구분한다. 내부 정책 코드, 디버그 JSON 및 해시는 제품 설명 화면에 노출하지 않고 별도 기술 기록에서 추적한다.

## 3. 가상 소비와 운영 전략

### 거래 집계

행동이 실제로 실행된 경우에만 등록된 상품의 SKU·수량·가격·과금 범위를 가상 거래 원장으로 전달한다. 객실 숙박, 식음, 시설·행사 이용은 고객부터 호텔 전체까지 단계별로 검산하며, 포함 혜택·실제 추가 결제·가정 가격·가격 미확인을 구분한다.

외부 배달은 호텔 안의 식음 선택과 경쟁하는 대안으로만 모델링하고, 배달 비용이 확인되지 않았다면 호텔 매출로 합산하지 않는다.

### 운영 A/B 설계

운영자의 질문은 “할인을 적용했나?”보다 **“어떤 고객이 왜 현재 업장을 선택하지 않았고, 우리가 바꿀 수 있는 조건 중 무엇을 실험할 수 있나?”**에 가깝다.

1. **목표 설정:** 업장 이용 유치, 상품 선택 변화, 외부 소비의 호텔 내부 전환 등 목적을 구체화한다.
2. **원인 진단:** 목표 업장이 선택 가능했는지, 아니면 영업·예약·상품 자격 등으로 후보에서 제외됐는지 구별한다.
3. **전략 가설:** 개인 근거·상황·반례에 연결된 운영 개입을 카드로 제안한다. LLM의 제안은 자동으로 승인된 실행 조건이 아니다.
4. **동일조건 A/B:** 같은 고객·방문·시나리오·판단 정책에서 등록되고 검증된 운영 변수 하나만 바꾼다. 가격 산술 재계산과 행동을 새로 결정한 실험은 구분한다.
5. **효과 분해:** 신규 업장 유입, 기존 업장 간 이동, 같은 업장 내 메뉴 변경, 할인가 적용 비용, 호텔 전체 가상 소비 순변화를 별도로 제시한다.

규칙 정책의 결정적 A/B와 LLM의 새 추론 기반 A/B는 증거 수준이 다르다. LLM은 같은 입력에도 결과가 달라질 수 있으므로 단일 차이를 운영 변수의 확정 인과효과로 주장하지 않는다. 지원되지 않는 상품·시간·예약 조건은 **실험 불가 또는 추가 확인 필요**로 남긴다.

## 4. 평가 설계와 확인된 결과

HILLINK는 정답률 하나보다 여러 층을 독립적으로 평가한다.

| 평가 층 | 확인하는 것 | 대표적인 오류 |
|---|---|---|
| **프로필·출처** | Fact와 원문·화자·시점·의미의 연결 | 타인 행동 혼입, 조건부 평가의 과잉 일반화 |
| **선택 전 판단** | 당시 보낸 Fact·상태·후보와 선택 이유의 일치 | 인용하지 않은 근거 주장, 선택 이유와 선택 충돌 |
| **연속 방문** | 식사·활동·휴식·기억·취침·퇴실의 연결 | 기계적 반복, 비현실적 종료, 잊힌 이전 식사 |
| **운영 계약** | 시간·시설 자격·SKU·가격·수량·포함 혜택 | 실행 불가능한 선택, 상품 이중 과금 |
| **거래 원장** | 고객 거래와 상품·업장·부문·호텔 합계 일치 | 영수증 불일치, 객실 박수 오류 |
| **운영 실험** | 같은 조건·한 변수만 변경, 고객 이동과 순변화 | 할인 비용을 신규 유입 효과로 오인 |
| **처리 효율** | 판단 지연·토큰·호출 수·비용과 UI 반응성 | 품질 개선 없이 호출·대기 증가 |

실호출 기반 비교와 저장 응답 재생, 규칙·합성 실행은 분리한다. 독립 모델 평가와 사람의 의미 승인을 동일한 절차라고 보지 않는다.

### 대표 검증 결과

| 항목 | 확인한 범위 | 의미 |
|---|---|---|
| 고객 프로필 | 45명 표시, 28명 기술 실행 가능 | 전체 프로필의 사람 의미 승인을 뜻하지 않음 |
| 상품·원장 | 등록 상품·수량·과금 계약 기반 다층 집계 | 실제 호텔 POS 매출이 아닌 가상 거래 |
| 실시간 판단 효율 | 비교 정책 평균 32.2초 → 10.1초, p90 51.3초 → 14.4초 | 호출 집합과 추론 설정이 다른 **정책 전체 비교** |
| 판단당 비용 | 비교 집합 $0.00503 → $0.00086 | 같은 기준 집합의 정책 비교 결과이며 보편적인 비용 보장 아님 |
| 개선형 연속 방문 | 대표 고객 4명의 전체 LIVE 방문·체크아웃·원장 일치 | 표본 범위의 실행 일관성, 미래 행동 정확도 아님 |
| 객실 저녁·취침 | 대표 방문에서 객실 체류와 실제 취침을 분리해 실행 | 모든 고객에게 동일한 취침 시각을 부여하는 규칙 아님 |
| 집단 운영 실험 | 규칙 엔진 28팀의 가상 A/B와 거래 차이 검산 | 28팀 LLM LIVE 또는 실제 운영 효과 실증 아님 |

개인 성향의 실제 인과적 기여, 행동의 현실 적합성, 할인과 실매출의 인과관계에는 추가적인 독립 비교와 현장 자료가 필요하다. 특히 실제 이용 자격·최신 메뉴·예약·수요·POS·대기·좌석 경쟁을 모두 반영한 운영 환경이라고 주장하지 않는다.

## 5. 구현 안내

### 재현과 독립 검증

[README](../../../README.md)의 기본 실행 경로로 설치하고, [RECOVERY.md](../../handover/RECOVERY.md)의 자료 복원·규칙 실행·정확 Replay·승인된 LIVE·원장 및 A/B 확인 절차를 따른다. 같은 저장 기록을 읽을 때에는 실행 정책, 입력 해시, 상품 계약, 고객 범위, 판단 출처를 함께 확인한다. 특정 실행의 성공은 다른 정책·방문·집단에 자동으로 일반화하지 않는다.

## 6. 참고한 연구

아래 문헌은 설계·평가 관점을 제공한 참고문헌이다. 원 논문의 실험 또는 정량 성과를 HILLINK가 그대로 재현했다고 주장하지 않는다.

- [Park et al., *Generative Agents: Interactive Simulacra of Human Behavior*](https://arxiv.org/abs/2304.03442): 기억·계획·회고와 연속 행동의 연결.
- [Park et al., *LLM Agents Grounded in Self-Reports Enable General-Purpose Simulation of Individuals*](https://arxiv.org/abs/2411.10109): 개인 자료 기반 에이전트와 독립 평가의 필요성.
- [Li et al., *How Far are LLMs from Being Our Digital Twins?* (BehaviorChain)](https://aclanthology.org/2025.findings-acl.813/): 단발 응답이 아닌 행동 사슬의 평가.
- [McFadden, *Conditional Logit Analysis of Qualitative Choice Behavior*](https://eml.berkeley.edu/reprints/mcfadden/zarembka.pdf), Train, *Discrete Choice Methods with Simulation*: 후보 효용·선택 구조에 대한 이론적 참고. 현재 엔진의 가중치를 검증된 수요 계수로 보지 않는다.
- [Grimm et al., ODD Protocol](https://doi.org/10.18564/jasss.4259): 에이전트 모델의 목적·상태·가정·절차를 명시하는 문서화 관점.

## 7. 공개·활용 범위

이 인계서는 시스템의 연구 방법, 아키텍처, 검증 가능한 실험 범위와 한계를 설명한다. 후기 전문·작성자 식별자·비공개 모델 요청/응답·API 키·개인 비용 원장·재배포가 확인되지 않은 이미지나 원출처 자료는 공개 설명 문서에 포함하지 않는다. **공개 가능한 기술 서술과 개별 데이터의 재배포 권한은 별도로 판단한다.**

HILLINK를 후속 개발할 때에도 개인 Fact의 원문 연결, 실행 근거, 정책별 결과 구분, 호텔 계약과 원장 정합성을 유지하는 것이 핵심이다.
